**#71, the atomic save.** A save writes a redo-only commit record, `.ithax-commit.json`, once every temporary file is synced. The renames follow, and then the record is removed.
- **Nothing is put back after the record.** A rename that fails keeps the record and the temporaries; the write is answered E186 ("the save is recorded"), and the next use of the folder finishes it.
- **Every use of a project folder replays a record left there.** That covers listing, opening, and every model, data and run use. A replay that cannot finish refuses the project with E186, and a listing shows the project as not available.
- **Locking.** One lock per folder, keyed by its resolved path, covers each whole commit and replay.
- **Filesystem errors.** Every filesystem error of a commit or replay maps to `CommitFailed` (`commit.FILE_ERRORS`: `OSError`, `ValueError`, `RuntimeError`).
- **Reads.** Every read of a project's model, `project.json` or column index is made inside one `ModelStore.settled(pid)` hold, which settles the folder under the project's lock.
- **Events.** A replay that finishes a save sends the `model` event, with `client` `null`.
- **Review.** Codex reviewed #182 in five rounds. Each finding was verified and fixed with a test that fails before the fix. Three classes were fixed through their helper, and `AGENTS.md` names each:
  - a recovery that pairs one revision with another's model;
  - a filesystem error escaping the commit;
  - a read in a hold that did not settle the folder.

**#82, small results.** There is no `/v1` change: `summary.json` and `GET .../summary` stay complete.
- **The finding.** `optimization_result` names at most 10 variables not at 0 and at most 10 tight constraints, then says how many others there are. When it cuts a list, it ends "Every value is in the results." The evidence keeps every value. In #82's 18,000-variable case the finding is now under 400 characters; it was 185,247.
