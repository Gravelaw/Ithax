From AKS-107 (this change, the pool, schedule and failure entry):

24. A pooled item holding a server unit while it waits for the pool unit is waiting: it counts in `queue_length` and for `shortest_queue`, and its unit is not busy in `utilization`. Candidate bucket: Phase 1a.
25. `queue_capacity` of a pooled server limits only the items waiting for a server unit. Candidate bucket: Phase 1a.
26. A finished item refused downstream keeps both its server unit and its pool unit; both are released together when it moves. Candidate bucket: Phase 1a.

28. A pooled server's `utilization`, `scheduled_fraction` and `availability` are over its own units; a schedule on its pool changes none of them; `<pool>.utilization` counts a unit held by a refused item as busy. Candidate bucket: Phase 1a.

30. A shift's capacity above the target's `capacity` is taken as that capacity (no error), so `scheduled_fraction` is at most 1. Candidate bucket: Phase 1a.
31. The capacity at time 0 applies before any event; later changes run in scheduling order with the other events at their instant. Candidate bucket: Phase 1a.
32. Under a schedule or failure the `utilization` time series is busy units, at most the available ones, over the available ones, 0 while none is available; its time average is then not the summary metric. Candidate bucket: Phase 1a.
33. `utilization` is NaN when no capacity is available over the whole observed period (server or pool). Candidate bucket: Phase 1a.
34. One `failure` block is one alternating process, so one unit at a time fails, and a server of capacity 2 or more always has availability 1. Candidate bucket: Phase 1a to confirm (one failure process per unit: Phase 2).
35. Which unit fails: an available unit holding no item; else the item in service that started last (suspended); else a unit with a refused finished item (which still moves on); else a unit whose item waits for the pool (its service starts at the repair). Candidate bucket: Phase 1a.
36. A failed unit counts against the scheduled capacity ("scheduled minus failed"), so a unit failing off shift leaves the next shift one unit short until its repair; the time to failure runs on calendar time from each repair. Candidate bucket: Phase 1a.
37. A suspended item resumes with its remaining time at the repair even if its shift has ended; while suspended it is neither busy nor waiting. Candidate bucket: Phase 1a.
38. The benchmark files: both resource-pool cases in one model with four extra rows (queue length, server and pool utilizations); the failure case checks availability only; exponential times; seeds 1009 to 1011. Candidate bucket: Phase 1a (the seeds: drop?).
