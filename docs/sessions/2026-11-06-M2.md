## Awaiting owner

Each of these is a reading taken without the owner under guide rule 5. Each is written into the spec and logged in DECISIONS. Each item names the PR and entry that raised it.

1. **Negative sampled times are set to 0 s** for every distribution, not only the `normal`, with no new issue code. This answers M1 item 9 ("Negative times are not reported") provisionally. W201 keeps the written mean except for the `normal`, so it underestimates the load of a server whose service time can fall below 0 s. Raised by PR #15 and the AKS-96 entries.
2. **Adapter discovery readings.** Raised by PR #16 and the AKS-97 entry.
   - An entry point whose class `name` differs from its entry-point name is left out and logged.
   - The process adapter is named `simpy`, and its `version` is the product version.
   - `Capabilities.hardware` is a tuple of words such as `gpu`, empty for none.
   - Adapters are discovered once per process, so an engine installed while the service runs is found after a restart.
3. **SimPy adapter core readings.** Raised by PR #17 and the AKS-98 entry.
   - The engine input layout, `engine/input.json`, leaves out `ui`, `label` and `meta`.
   - Draw order: one stream per component, samples in event order; a source draws after creating an item, a server when a service starts.
   - A source's first item is created at `first_arrival`, 0 s when absent, and the source stops after `max_items` without another draw.
   - The warm-up boundary: an event at the warm-up instant counts, and `queue_length.max` takes the value held at the end of warm-up and values held for no time.
   - A mean over no items is NaN, and its row is still written.
   - Units are `s`, `1/s` and `1`.
   - Every server reports `availability` and `scheduled_fraction` as 1 until M4.
   - Workers use the `spawn` start method; output is written only on completion, and a cancelled run writes nothing.
4. **Delay, branch, blocking and time-series readings.** Raised by PR #18 and the AKS-99 entry.
   - A unit holding an item its next block refused counts as busy in `utilization`.
   - Blocked items move as soon as space frees, at the same instant, in the order they were refused.
   - A branch always accepts; a refused item waits at the branch without limit, so a source feeding a branch never discards. A delay holds a refused item past its time.
   - The route is chosen when the item arrives; `probability` draws once per item, even with one weight above 0; `shortest_queue` never draws and ignores `weights`; a server's waiting items are its queue, not its units.
   - The time-series metrics are `<server>.queue_length`, `<server>.utilization` (busy units over nominal `capacity`; M4 decides the denominator under a schedule) and `model.wip`, unit `1`, ordered by metric then time.
   - Samples start at 0 s, include warm-up, stop before the end, take the value after the events of their instant, and a time within 10⁻⁹ × `record_interval` of the end counts as the end.
5. **A model whose items circle zero-time blocks forever never finishes.** For example, a `shortest_queue` branch routed back to itself. It can be cancelled, but nothing flags it; flagging it at validation needs a new issue code, which is the owner's decision. Raised by PR #18 (second review) and the AKS-99 entry.
6. **Benchmark file readings.** Raised by PR #19 and the AKS-100 entry.
   - Every M2 arrival, service and delay time is exponential; spec 2 gave only means for the tandem and delay rows and "30/h" for the branch.
   - An `exact` check passes when the estimate and the answer, each rounded to four significant figures, are equal.
   - A missing metric or a NaN replication value fails a check.
7. **Example targets judged on the mean.** The three-machine line and warehouse targets are checked on the across-replication mean, not on its interval; the theory values of those two files are reported in spec 2 but not gated (the line's paint wait is 3.3 standard errors below theory at seed 12345, and within 1.7 at seeds 1, 2 and 7). Only the coffee shop is gated on theory. The M/M/1 and M/M/2 rows of spec 2's prototype table keep the prototype's numbers, with the benchmark results beside them. Raised by this change and the AKS-101 entry.
8. **Example files.** Still owner decision 1 (AKS-74): confirm `three_machine_line.json` and `warehouse.json`, now measured and on target, or supply the originals. Raised at M1 (PR #13, AKS-93).
