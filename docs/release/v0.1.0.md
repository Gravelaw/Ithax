# Releasing v0.1.0 (#103)

How v0.1.0 goes from `main` to a tag. Sessions prepare and check every step up to the tag. The owner makes the tag and the GitHub release (owner decisions, 2026-11-15, item 2). Phase 2 goes on in `main` meanwhile, so the release is made on a branch: option A, the orchestrating session's choice of 2026-11-15.

## The release branch

- **`release/0.1`** is cut from `main` once Phase 1a's last PRs have merged: #212, the owner checks list, and the PR that adds this file and `CHANGELOG.md`. Its branch point is recorded in `docs/DECISIONS.md`.
- **Nothing is developed on it.** It takes two kinds of change:
  - the version PR, which sets 0.1.0 and dates the changelog;
  - cherry-picks of fixes that merged to `main` first, such as fixes the owner checks need (`docs/release/v0.1.0-owner-checks.md`).
- **Every change reaches it by a pull request into `release/0.1`.** CI runs on those PRs, since both workflows run `pull_request` for any base branch, and `all-green` decides them as on `main`. A push to `release/*` also runs `checks`, so the commit to be tagged has its own run. The orchestrating session merges them, under the same gate as `main`: `all-green` passes, Codex is clean on the head, no review thread is open, and the PR merges cleanly.
- **`main` moves to `0.2.0.dev0`** in a PR of its own, right after the branch is cut. Phase 2 builds then never say 0.1.0.

**Owner, before the branch takes its first PR:** the ruleset that protects `main` (retrospective P4) may not cover `release/*`, and a session cannot change rulesets. Add `release/*` to it, or protect the branch, with the same rule: `all-green` required, no direct pushes.

## The version PR (into `release/0.1`)

The product's version is in six places. `tests/test_package.py` checks that `Cargo.toml`, `tauri.conf.json` and `package.json` agree with `__version__`, in semver spelling. The two lock files carry the version too, and the same PR changes them, for example with `cargo update -p ithax-desktop --offline` and `npm install --package-lock-only` in `desktop/`:

| File | From | To |
| --- | --- | --- |
| `src/ithax/__init__.py` (`__version__`) | `0.1.0.dev0` | `0.1.0` |
| `desktop/src-tauri/Cargo.toml` | `0.1.0-dev.0` | `0.1.0` |
| `desktop/src-tauri/Cargo.lock` (`ithax-desktop`) | `0.1.0-dev.0` | `0.1.0` |
| `desktop/src-tauri/tauri.conf.json` | `0.1.0-dev.0` | `0.1.0` |
| `desktop/package.json` | `0.1.0-dev.0` | `0.1.0` |
| `desktop/package-lock.json` (two entries) | `0.1.0-dev.0` | `0.1.0` |

`CHANGELOG.md`'s heading "[0.1.0] - not yet released" takes the date in the same PR. That date is the day the owner expects to tag, and is moved if the tag comes later.

Checks, run on the PR and copied with their run ID (guide "Numbers in the record"):

- `bash scripts/check.sh`, `pytest -m benchmark` and `pytest -m template`;
- the interface's `npm run check`, `npm run build` and `npm run e2e`;
- the `package` job. It builds `ithax-0.1.0-linux-x86_64.tar.gz` and `ithax-0.1.0-x86_64.AppImage`, each with its `.sha256`, and tests both, offline and mounted. Its artifact `ithax-linux-x86_64` holds the files the release publishes.

## The tag and the release (the owner's)

Once the owner checks are done and the version PR has merged:

1. On `release/0.1`, check that the last run of `checks` on the branch head passed: Actions, the push run for that commit.
2. Tag that commit: `git tag -a v0.1.0 -m "Ithax 0.1.0" <sha>` and `git push origin v0.1.0`, or create the tag with the release in the next step.
3. Create the GitHub release for `v0.1.0`:
   - its notes are `CHANGELOG.md`'s 0.1.0 section;
   - attach the four files from that run's `ithax-linux-x86_64` artifact: the archive, the AppImage and their `.sha256` files;
   - say that the packages are unsigned and how to check the checksum (spec 0 "Risks").
4. Check 7 of the owner checks decides whether the release is public or limited to testers. A public release first needs the trademark search and the lawyer's review.

## After the tag

- Sessions record the tag's commit in `docs/DECISIONS.md` and close #103.
- A later 0.1.x release is a cherry-pick PR into `release/0.1`, a version PR to `0.1.1` and a new tag, by the same steps.
